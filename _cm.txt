feat: Google OAuth UI + fix auth pages prerendering the feature flag

Two real defects found by auditing auth, not from the PRD list:

1. Google OAuth had no UI at all
   auth.config.ts registered the Google provider conditionally, but
   neither /login nor /register rendered any trigger. Supplying
   AUTH_GOOGLE_ID/SECRET would still leave no way to sign in.
   Added GoogleSignInButton + isGoogleEnabled() flag. The button is
   gated so it never appears in a state where it cannot work, and only
   a boolean crosses to the client (the secret stays server-side).

2. Auth pages prerendered the flag at build time
   /login and /register were static (○), so isGoogleEnabled() was baked
   in during `next build`. Enabling Google later and restarting would
   never surface the button. Now force-dynamic (ƒ).

Also:
- Split login/register forms into client components so the pages can be
  server components that resolve the flag server-side.
- isGoogleEnabled() lives in its own module: lib/auth/actions.ts is
  'use server', where every export must be async.
- test:ocr-real now SKIPS (exit 0, clearly reported) on Gemini upstream
  429 instead of failing — free-tier quota exhaustion is not an app bug,
  but silently passing would hide a real regression.

Verified both directions of the flag: OFF -> hidden, ON -> visible,
and the OAuth secret never appears in the HTML.

test:google-flag 9/9. Total 142 checks green across 15 suites.
