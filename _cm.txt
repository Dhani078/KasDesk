test: exercise the real Zod schemas with hostile input (29 checks)

The schemas look strict — integer, positive, max 100 billion — but a schema
only protects the paths that actually run it. This drives the REAL
TransactionSchema / WalletSchema / DebtSchema directly.

Why schema-level rather than over HTTP: calling the server action needs its
build-generated action id, which changes every build. I tried the HTTP version
first and it "passed" 9/9 for the wrong reason — Next rejected every request
before validation ran, so the balance never moved because nothing executed.
That is a false sense of security, not a test. Deleted it.

The cases worth naming are the ones that would CORRECT money if they slipped
through:
  - negative expense  -> would silently ADD funds
  - zero amount       -> junk row in the history
  - fractional amount -> breaks the integer-money invariant
  - NaN / Infinity / string amounts, over-max, missing wallet, transfer to self

Also asserts the schemas do NOT over-block: exactly-at-max amount, 120-char
title, valid transfer, category tag, note — all still accepted. A validator
that rejects legitimate input is its own bug.

Result: all 29 pass. No schema defects found.
