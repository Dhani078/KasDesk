fix: extend archived-wallet guard to vault deposits and withdrawals

The guard from the previous commit covered only createTransaction. Auditing
every path that mutates a wallet balance found two more:

  - depositToVault    — money leaves a wallet
  - withdrawFromVault — money arrives at a wallet

An archived DESTINATION is just as lossy as an archived source: the balance
rises while Total Saldo stays flat, so the money still disappears from view.
Both now select isArchived and throw WALLET_ARCHIVED, translated to a clear
Indonesian message.

deleteTransaction is deliberately EXEMPT, and this is the interesting part.
It also moves money, but it REVERSES an existing transaction. Blocking it
would strand money: a user who archived a wallet could never delete its old
transactions, leaving the balance permanently frozen. Reversal must always
be possible, so the guard is intentionally absent there.

That exemption is easy to mistake for an oversight, so test-archived-coverage
asserts it by name: deleteTransaction must NOT call the guard, and the source
must document why. A future refactor "fixing the inconsistency" has to update
the test and confront the consequence.

Also adds a coverage test (20 checks) that parses lib/actions.ts to confirm
every balance-mutating path selects the flag, calls the guard, and translates
the error — so a new money path added later cannot quietly skip it.
