feat: LogoutButton — sign-out control + cache purge

Two findings from the PWA audit:

1. There was NO sign-out control. logoutAction existed but nothing called it,
   so a signed-in user could not end their session from the UI.

2. The service worker caches authenticated HTML (pages NetworkFirst, 24h)
   because the PRD requires offline use (G6 / FR-OFF). On a shared phone the
   next person could be served the previous user's dashboard from cache.

Added LogoutButton on the home header: calls logoutAction and best-effort
purges all caches first (never blocks sign-out if the browser refuses).

The test drives the REAL signout endpoint: logged-in / and /wallets render
200; after sign-out both redirect again, so the session genuinely ended.

While re-running the suite, dashboard-math and wallet-archive broke — the new
button's inline SVG sits between "Total Saldo" and its value, and its label
contains "Keluar". Both were TEST bugs, not app bugs:
  - afterLabel scanned only 400 chars; widened to 4000 (SVG is ~600 chars)
  - shownTotal used a hard 300-char slice; now uses afterLabel
  - "Keluar" now anchors after "Masuk" so it cannot match the logout button
    and read the wrong number (it was picking up Total Saldo)

279 -> 289 checks green across 28 suites. DB clean (1 demo user).
