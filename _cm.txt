test: verify real signup seeds a complete account; add fixture cleanup

Two problems found while auditing test hygiene.

1. test:newuser-seed was silently vacuous. It tried to sign up through
   /api/auth/callback/register, a route that does not exist (registration is a
   server action), so it always skipped and only a passive scan ran — the real
   signup path was never verified. Rewritten to call registerUser() directly
   through tsx, which is the same function the action calls. Now 4 checks:
   user created, has a wallet, has the 9 system categories, and no real user
   is missing seed data.

   Note: tsx needs --env-file=.env.local here. Without it process.env.DATABASE_*
   is empty and the DB pool fails with an opaque AggregateError — the test now
   reports that rather than passing.

2. Test debris was piling up in the database: 7 of 8 users were leftover
   fixtures, because most scripts insert users straight through SQL and
   sometimes fail before cleanup. That made the integrity scan look like real
   corruption. Added scripts/cleanup-fixtures.js — report-only by default,
   --apply to delete — matching only <prefix>-<ms-timestamp>@example.com, so
   it cannot touch a real account. Ran it: 8 users -> 1 (the demo user).

Also scanned all 115 tracked project files for secrets: the only matches are
process.env references and deliberately-wrong test passwords. No credentials
in the repo. (The 62 hits in .agents/skills are example code in that
documentation, not project code.)

211 checks green across 22 suites.
