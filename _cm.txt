feat: wallet archiving — the isArchived column could never be set

Same class of defect as the Google OAuth button: a feature that existed in the
backend but had no way to be reached from the UI.

The isArchived column was:
  - defined in the schema
  - filtered on by getWallets()
  - guarded in every money-moving path (11.26, 11.27)

...but no action and no UI could ever SET it. An unused wallet was stuck in
Total Saldo forever with no way to retire it.

Added archiveWallet(id, archived), owner-scoped, plus an archive button with a
confirm step (archiving a funded wallet removes that money from Total Saldo —
correct, but surprising on a mis-tap) and a restore button.

The important design point: /wallets now uses getWalletsIncludingArchived and
lists archived wallets in a separate section. Archiving on top of the existing
getWallets() filter would have been a ONE-WAY DOOR — the wallet disappears
from every list with no way back, which is worse than having no feature. The
test asserts the archived wallet is still listed and restorable.

Also verified cross-user isolation: archiving is scoped by (id AND userId), so
one user cannot archive another's wallet.
